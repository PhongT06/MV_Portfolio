      • Purpose/Goals:

        Cashflow Guru is a modern full-stack personal finance and budgeting application designed to go beyond passive expense tracking by delivering actionable, personalized financial guidance. Traditional budgeting tools often limit themselves to logging income vs. expenses without providing clear strategies for accelerating debt payoff or hitting savings targets faster. This project addresses that gap by enabling users to input monthly income, categorize and track expenses, define debt obligations (with interest rates/balances), set savings goals, and receive tailored advice — including suggested expense reductions, optimized debt repayment sequences, and accelerated savings plans — powered by calculated projections and intelligent recommendations.

        Built as my final Multiverse bootcamp capstone project, Cashflow Guru aimed to deepen full-stack TypeScript proficiency across React (frontend), Node.js/Express (backend), and Prisma ORM with a database backend. As a solo developer, I followed a structured, incremental development approach — starting with core data models and CRUD, progressing to user input flows, financial calculations, and finally integrating the advice-generation logic. This mirrored professional engineering workflows: defining user stories, building iteratively, handling deployment challenges, debugging cross-stack issues, and refining UX for clarity and reliability. The result is a production-ready tool that demonstrates end-to-end ownership of a meaningful real-world application while practicing clean architecture, type safety, and problem-solving under constraints.

      • Overview of Features:

      Back End Module Project

      Must include:

      • Link to repo
      • The Wish Granting API Repo
      • Purpose/Goals:

        The Wish Granting API was developed as our Back-End Module project to practice building a well-structured, fully documented RESTful API using Node.js, Express, and a relational database. The goal of the project was to design and implement a backend service that allows users to create, view, update, and delete “wishes” through clearly defined endpoints while applying best practices in routing, validation, error handling, and asynchronous database operations.

        This project focused on strengthening core back-end engineering fundamentals — including data modeling, controller logic, layered architecture, and writing modular, maintainable code. Our team also emphasized collaboration through GitHub workflows, PR reviews, and iterative improvements. By completing this API, we learned how to design scalable endpoints, manage application state on the server, and ensure reliable behavior through consistent HTTP responses and validation patterns.

      • Overview of Features:
        • User Authentication (Local + Google OAuth 2.0): Supports two authentication flows: traditional username/password login with bcrypt hashing, and Google OAuth 2.0 sign-in using Passport and the Google Auth Library. Both authentication flows issue a signed JWT used to access protected API routes.
        • JWT-Protected Endpoints: All core resource routes (Users, Wishes, Fairies) are protected by JWT middleware. Authenticated users receive access to their own data, while admins receive elevated privileges.
        • User Registration & Login: Local signup endpoint creates new users with hashed passwords; login verifies credentials and returns a JWT. A dedicated /auth/google route handles Google provider login and auto-creates users on first OAuth sign-in.
        • CRUD for Wishes: Users can create, view, edit, and delete their own wishes. Admins can view and manage all wishes. Each wish includes text, category (fun/practical/chaotic), associated user, timestamp fields, and an optional generated outcome.
        • Fairy Management (Admin-Only): Full CRUD operations for Fairies, protected by requireAdmin middleware. Fairies include name, specialty, status, description, and a linked user_id, and return joined User data in responses.
        • Role-Based Authorization: Access control enforcing:
          • Basic users see and modify only their own wishes.
          • Admins can view, edit, or delete any user, wish, or fairy.
          • Error responses clearly distinguish unauthorized (401), forbidden (403), and invalid input (400).
        • Associated Data Retrieval: Wish and Fairy endpoints return relational data by joining associated User records, improving API usability for frontend integrations.
        • Gemini AI Wish Outcome Generation: When granting a wish, the API optionally calls Google Gemini (via fetch + API key) to produce an ironic, humorous magical outcome in the style of The Fairly OddParents, storing the generated text as the wish's outcome.
        • Comprehensive Validation & Error Handling: Input validation for IDs, wish text length, category values, required fields, and Sequelize model validation errors. Central error handling middleware returns structured, consistent error messages for debugging and client clarity.
        • Testing with Jest + Supertest: Automated tests cover authentication flows, CRUD operations, error scenarios (404, 401, 403, 400), and database isolation. Gemini calls are mocked to ensure test consistency and speed.
        • Database via Sequelize + SQLite: Includes relational models (User, Wish, Fairy), model associations, validation rules, lifecycle hooks (password hashing), and deterministic test DB resets.
        • Tier-Based Feature Delivery: All features were built incrementally following the module's tier progression:
          • CRUD basics (Tier 1)
          • Password hashing + OAuth (Tiers 2-3)
          • Authorization + JWT protection (Tier 4)
          • Associated users in responses (Tier 5)
          • Admin role + elevated access (Tier 6)
          • Gemini integration + bonus endpoints (Bonus)
      • Your specific contribution in the team:
        • Implemented full CRUD functionality for Wishes: Built the Wish model, created the RESTful routes, added input validation, implemented category support (fun/practical/chaotic), and handled relational lookups to include the associated User in responses.
        • Added category-based filtering for wishes: Enhanced the GET /wish endpoint to support category filtering, user-based filtering, and safe validation for invalid categories.
        • Implemented Fairy CRUD: Built the full CRUD routes and the Fairy Sequelize model, including validation rules, associations to Users, and admin-only protections using requireAdmin middleware.
        • Developed the frontend API client (WishAPI class): Created a reusable API wrapper that handles authentication headers, token storage, error handling, parsing JSON responses, and exposes helper methods (login, getWishes, getWish, createWish, updateWish, grantWish, etc.).
        • Integrated frontend with backend authentication: Implemented JWT-based login/logout, user persistence in localStorage, session expiration handling, and user role detection for showing admin views.
        • Built the Dashboard, Wishes, and Fairies frontend pages: Wrote logic to load user info, fetch statistics, render wishes/fairies dynamically, and control UI behavior based on user roles (e.g., only showing admin forms to admins).

        • Full-Stack Development: Implemented features across the Express/Sequelize backend and a vanilla JS frontend (dashboard, wishes, fairies) with authenticated API calls and role-aware UI behavior.
        • RESTful API Design: Built and refined CRUD endpoints for Wishes and Fairies, including list/detail routes, PATCH updates, and structured JSON responses with associated User data.
        • Authentication & Authorization: Implemented local login (bcrypt-hashed passwords), Google OAuth → JWT issuance, and JWT-protected routes; enforced RBAC with admin-only fairy management and user-scoped access for wishes.
